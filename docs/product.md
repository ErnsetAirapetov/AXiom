# Продукт

## Проблема

Требования к проектированию автомобильных дорог размазаны по сотням
документов (ГОСТ, СП, СНиП, ОДМ, ОДН, ГЭСН/ФЕР, региональные ТУ, ведомственные
нормы Росавтодора и ГК «Автодор»), которые противоречат друг другу и меняют
редакции. Проверка актуальности — ручная. Вдобавок половина реального
проектного знания вообще не записана в нормативах: она живёт в замечаниях
экспертизы и в головах проектировщиков. Уходит человек — уходит знание.

## Цели

- Дать проектировщику один вход для вопроса на естественном языке вместо
  ручного перебора документов.
- Показывать дословную норму со ссылкой на источник, а не пересказ без
  привязки.
- Явно разделять «что требует норматив» и «что является практикой/опытом»,
  не смешивая их в одном утверждении.
- Показывать противоречия между источниками, а не разрешать их молча за
  проектировщика.

## Как это работает (укрупнённо)

1. Проектировщик задаёт вопрос на естественном языке.
2. Система ищет по всей нормативной базе и, отдельно, по экспертному слою
   (замечания экспертизы, заметки экспертов).
3. В ответе — сводка по сути и дословные цитаты с указанием документа, пункта
   и редакции; экспертные заметки визуально отделены от нормативных цитат.
4. Если по вопросу ничего не найдено — система так и говорит, не выдумывает
   ответ.
5. Если источники противоречат друг другу — противоречие показывается, а не
   скрывается за одним «правильным» ответом.

## Флоу пользователя (базовый)

Проектировщик формулирует вопрос → получает сводку + цитаты со ссылками →
при необходимости раскрывает полный текст пункта и историю редакций →
использует ответ как опору для своего решения. Финальная ответственность за
проектное решение остаётся на проектировщике — система не проектирует и не
подтверждает соответствие нормам юридически значимым образом.

## Кому предназначено

Внутренний инструмент проектного отдела/компании, не публичный SaaS-продукт.
