# Журнал решений

Формат: `Рn: дата, решение, причина, отвергнутые альтернативы`.

- **Р1**: 2026-08-04 — Фордж проекта: GitHub, репозиторий публичный, главная
  ветка `main`. Причина: соответствует уже существующей настройке репозитория
  (`.claude/forge.md`, `.claude/harness.json`). Отвергнутые альтернативы: не
  рассматривались, репозиторий уже создан на GitHub.
- **Р2**: 2026-08-04 — Технологический стек намеренно не выбирается на
  стадии изысканий. Причина: ключевые вопросы (где живут данные — контур vs
  облако; как измерять качество ответа; правовой режим текстов нормативов)
  прямо влияют на выбор технологий и ещё не решены владельцем. Отвергнутые
  альтернативы: выбрать стек заранее «по умолчанию» — отклонено, чтобы не
  создавать ложное ощущение решённости и не тянуть за собой не проверенные
  предположения.
- **Р3**: 2026-08-04 — Гейты харнеса (`checks`/`editChecks`) оставлены
  пустыми, `strict: false`. Причина: кода ещё нет, проверять нечем; гейты
  добавятся вместе с первым манифестом стека. Отвергнутые альтернативы:
  завести формальные, но бессмысленные проверки заранее — отклонено.

- **Р4**: 2026-08-04 — На стадии изысканий `main` не защищается: защита ветки
  на GitHub не включается, а локальный гейт `guard-git` ослаблен через
  `protectedBranches: ["__research-stage-no-protection__"]` в
  `.claude/harness.json` (указана несуществующая ветка, поэтому реально не
  защищено ничего). Причина: решение владельца — на стадии изысканий
  меняются в основном документы, и процесс «ветка → worktree → PR» на
  каждую правку даёт издержки без пользы. Отвергнутые альтернативы:
  (а) оставить гейт и выполнять коммиты руками владельца — отклонено как
  замедляющее работу; (б) пустой список `protectedBranches` — не работает,
  гейт в этом случае подставляет `mainBranch`.
  **Условие возврата: восстановить `["main"]` и включить защиту ветки на
  GitHub при переходе от изысканий к разработке (появление первого кода).**
